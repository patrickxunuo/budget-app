# System Patterns

## Project Structure

- `src/app/`: App Router pages, layouts, and framework error boundaries.
- `src/components/`: shared presentation components.
- `src/components/pwa/`, `src/components/theme/`, `src/components/app-shell/`: installability, colour-scheme, and navigation shell.
- `src/lib/theme/`: theme preference resolution and the WCAG contrast helpers the palette gate uses.
- `public/sw.js`, `public/icons/`: the service worker and the icons generated by `scripts/generate-pwa-icons.mjs`.
- `src/lib/env/`: public and server environment contracts.
- `src/lib/supabase/`: browser, SSR, and privileged server client factories.
- `src/lib/plaid/`: server-only Plaid integration.
- `e2e/`: Playwright browser journeys.

## Naming Conventions

- TypeScript files: kebab-case where descriptive; App Router framework filenames where required.
- Components and types: PascalCase; functions and variables: camelCase.
- Database tables and columns: snake_case.

## Code Patterns

- Server-only secrets: privileged modules import `server-only`; only `NEXT_PUBLIC_*` values may enter browser code.
- Supabase boundaries: separate browser, SSR, and service-role client factories.
- Authorization: database RLS is the primary boundary; privileged server paths must be narrow and documented.
- Auth lifecycle mutations: expose setup and invitation finalization only to the service role; expose membership changes only through fixed-search-path RPCs, and revoke direct table writes that could bypass recent-password checks.
- Cross-system deletion: enqueue Auth identity deletion transactionally before deleting database state, process the service-only outbox idempotently, and retain failures for a bearer-protected retry worker.
- Destructive workspace lifecycle: page every Plaid Item and cross the provider boundary through durable claim phases before local purge; serialize optional member emails with service-only recipient claims and deterministic message IDs; let only a service-role finalizer choose notification policy while it rechecks actor ownership, recent confirmation, current membership coverage, and exact workspace name.
- CSV portability: export through the same complete scoped/filter-aware read model as the displayed ledger, serialize only an explicit safe-column allowlist, use UTF-8 RFC 4180 output, and neutralize user-controlled spreadsheet formula prefixes without treating trusted numeric amounts as text.
- Plaid lifecycle mutations: keep pending candidates and encrypted access tokens service-only, revoke authenticated writes to protected Item/account state, and activate reviewed accounts through one fixed-search-path RPC.
- Plaid client callback boundaries: treat nullable SDK success values as failures before they cross into typed exchange/service calls; clear pending client state and return the member to sanitized, retryable UI instead of casting the absence away.
- Plaid duplicate identity: compare immutable provider-backed institution, type/subtype, normalized name, and mask fields; never use user-editable display names, and fail closed when duplicate lookup cannot complete.
- External activation boundaries: once database activation commits, downstream import failures are retryable pending states rather than false activation failures; return only sanitized sync state and preserve idempotent partial progress.
- Plaid transaction sync: claim each Item with a request ID, buffer the complete `/transactions/sync` page pass, then commit changes and the final cursor in one service-role RPC with cursor/claim/Item-state revalidation; persist only sanitized retry and support correlation state.
- Plaid login-repair recovery: Plaid Link success and account reconciliation are not proof of restored transaction access. Run a member transaction sync after reconciliation and clear sticky `needs_login_repair` plus prior login errors only inside the successful atomic sync commit; notify sibling client status only from that committed result, while failed/cancelled paths remain repair-required.
- Transaction accounting: retain provider amounts in Plaid's source convention and user choices in `transaction_metadata`; convert to safe integer cents at the domain boundary, classify with exact primary/detail mappings (never merchant-name substrings), exclude transfers from ordinary totals, net refunds against category spending, and reconcile pending predecessors before aggregation.
- Complete ledger reads: page through Supabase's configured row cap with stable unique ordering before calculating summaries or CSV exports; apply shared scope/date/category filters before display slicing so pagination never changes accounting totals.
- Transaction explorer pagination: derive opaque cursors from the deterministic `date DESC, source ASC, id ASC` display order after every result filter, report the complete matching count before slicing, and keep summary/CSV semantics independent of the page. Buffer server pages separately from responsive reveal depth (10 mobile, 50 desktop), invalidate continuation work on any query change, and never encode cursor or visible depth in the URL.
- Financial read scopes: every dashboard, transaction, and Manual/Cash list read requires an explicit Family or signed-in-member Personal scope; never aggregate or expose a Combined privacy view, and apply pending reconciliation before range/search filters.
- Transaction workflow routes: keep the landing overview read-only and free of management-only fetches; place Manual/Cash and Plaid mutation workbenches on independently authorized scoped routes. Carry a canonical relative overview URL through management links, accept a return target only when it resolves to the exact `/transactions` path, and give each child route its own geometry-matched loading fallback.
- Monthly budgets: store safe CAD cents in effective-dated, non-overlapping category versions; serialize create/revise/archive RPCs by privacy-domain/category advisory locks, mutate only the current open version, preserve historical cutoffs, and expand dashboard targets once per touched local calendar month.
- Manual/Cash ledger: keep off-bank rows accountless and outside Plaid reconciliation; mutate them only through fixed-search-path RPCs, preserve immutable scope/authorship, use audited soft deletion, and combine their explicit signed kinds with Plaid only at the accounting boundary.
- Session security: bind signed HttpOnly recovery and absolute-session state to the Auth user; recovery state is short-lived and single-use, while protected sessions expire absolutely after 30 days.
- RLS helpers: place narrow `security definer` predicates in the non-exposed `private` schema, pin `search_path`, revoke default execution, and authorize both a child row and its underlying parent privacy domain.
- Privacy-domain invariants: scoped category references must match workspace/scope/owner; deferred triggers enforce cross-table owner consistency; guarded scope fields prevent shared data from being privatized indirectly.
- Merchant categorization: derive stable merchant identity again inside authenticated mutation RPCs, treat provider entity IDs as opaque case-sensitive values, normalize only name fallbacks, and keep manual overrides above rules and Plaid defaults.
- Service-worker caching: the worker is deny-by-default and caches only same-origin GET responses whose path is on an explicit static allowlist (content-hashed `/_next/static`, icons, manifest, favicon, `/offline`); `/api/**`, every application document, non-GET, range, and cross-origin requests are passed through untouched, and navigations are network-first with no write path. Never widen that allowlist to anything that can carry member data.
- Service-worker updates: never `skipWaiting()` inside `install`; promote a waiting worker only when the page posts `SKIP_WAITING` after the member accepts, show the prompt only when a controller already exists, and latch the single `controllerchange` reload so an update cannot loop.
- Colour tokens: `--on-accent` is the only foreground allowed on `--brand`/`--brand-strong`/`--mineral`/`--alert` (plain white fails in dark mode); `--line` bounds interactive controls at 3:1 while `--line-soft` is decorative-only. `src/lib/theme/contrast.test.ts` parses `globals.css` and fails the build on any regression, so palette edits are checked, not reviewed by eye.
- Theme preference: device preference is the default, an explicit choice is stored under `budget-app-theme` and applied as `data-theme` by an inline `<head>` script before first paint; any control reflecting it must read through `useSyncExternalStore` with a server snapshot, because a lazy `useState` initializer reading storage is a hydration mismatch.
- Live regions: mount `role="status"` regions empty and toggle only their contents — a region inserted with its text already present is not announced. The shell always carries two, so browser assertions on a page's own status must be scoped. Testing this needs the right instrument: RTL's `render` flushes effects, so it reports a filled region either way; assert against `renderToStaticMarkup`, because the mount output is what decides whether AT announces. A second corollary bites in tests: `await findByTestId` on an always-mounted region resolves on its first query pass and does **not** wait, so assert with `waitFor` on the region's _contents_. A conditionally-rendered region is safe with `findBy*`; an always-mounted one is not, and the difference is invisible at the call site.
- Route loading fallbacks: give every authenticated segment its own `loading.tsx` and have it reproduce that route's own `<main id="main-content" tabIndex={-1}>`, container width, and padding — the skip-link target has to exist throughout loading, and a fallback with different geometry shifts the page when real content swaps in. Placeholders are `aria-hidden` shapes with no text and no figures, and the busy state is `aria-busy` plus one empty-mounted `role="status"`. The `loading.js` caveat about a layout reading runtime data does not apply to a _shared_ parent layout: `(app)/layout.tsx` awaits `requireActiveMembership()`, but a sibling tab switch never re-renders it, which is exactly why the shell stays mounted.
- Reduced motion: the global `prefers-reduced-motion` block only clamps `animation-duration`/`iteration-count`, which parks a _translating_ animation on its end frame rather than removing it. Any sweep or slide needs its own reduce rule that deletes the animation outright (`content: none` on the pseudo-element), placed in the same layer and after the base rule so it actually wins.
- Inline pending hints: `useLinkStatus` comes from `next/link` (not `next/navigation`) and only reports for a link it is a descendant of. Render the hint unconditionally at a fixed size and reserve space with opacity/visibility — never conditional mounting, which resizes the control under the pointer that just activated it — and delay its fade ~100ms so a prefetched, instantly-committing route shows no flash. A prefetched destination skips the pending phase by design, so any test of the hint must refuse the prefetch.
- URL-as-view-state: a client surface that syncs filters into the address bar with `history.replaceState` must not perform that sync from a response that lands after the component unmounted. Clearing the debounce timer is not enough — once the timer has fired the fetch continuation is uncancellable, and a request-id guard cannot catch it because the ref it compares against belongs to the unmounted instance. Set a `cancelled` flag in the effect cleanup and check it before every post-`await` side effect, or the URL ends up naming a view the member has already left.
- Plain-URL reconciliation: when a preserved client surface observes navigation to a URL with omitted defaults, parse those defaults against the current product-timezone date rather than the component's original reference prop. Otherwise returning from a historical query to a plain route clears visible filters but silently retains an old period.
- Seeding a client component from server props: a component that seeds `useState` from props ignores every later prop change, so it needs a `key` that changes on any navigation whose meaning differs. A key derived from the applied query covers scope switches, shared links, and back/forward. It cannot cover a return to a URL the server already rendered once — the server sees identical input both times — so reconcile against `useSearchParams()` if that case matters.
- Skip links: target each route's own `<main>`, never a wrapper around the whole shell, or "skip" lands above the navigation it exists to bypass.
- Metadata icons: declaring `metadata.icons` suppresses every `app/icon.*` and `app/favicon.*` file convention, so list those files explicitly whenever any icon is configured.
- In-page pending actions: use one `usePendingAction` instance per mutation surface. Its default exclusive strategy must claim a synchronous ref before invoking work so same-turn repeat activation cannot cross an API/provider boundary; use `latest` only for intentionally superseding reads, where a monotonic action id prevents stale work from clearing newer pending state. `PendingButton` keeps idle and progress labels mounted in one grid cell, hides the inactive label from both layout paint and the accessibility tree, and owns the single polite progress announcement; any legacy surface status should remain visible but announce only completion/error. Verify footprint and reduced motion with the actual component output plus computed browser styles—jsdom geometry and regexes over `globals.css` are not acceptance evidence.
- Interactive SVG charts: derive coordinates from the data domain rather than array indexes, include zero in a rounded scale, and render only the active responsive tick set through a hydration-safe `useSyncExternalStore` viewport subscription. Keep mouse hover temporary, touch selection pinned until outside interaction, keyboard readings arrow-navigable/Escape-dismissible, and the always-mounted live region empty in static markup; retain a complete semantic table as the non-visual fallback.
- Playwright state assertions: drive disclosures through their actual trigger, then auto-wait for the parent open state and nested control visibility before interacting; `isVisible()` and immediate `count()` snapshots are not synchronization. Responsive client state may initially reflect the server snapshot, so derive expected cardinality from fixture-backed source rows and use retrying locator assertions such as `toHaveCount`. Role locators exclude hidden semantic fallbacks by default, so use `includeHidden` or a structural locator when counting rendered-but-visually-hidden source rows. Test responsive behavior at representative widths safely away from CSS breakpoint edges, and poll `window.innerWidth` on the loaded application document before asserting layout; a mobile-emulated `about:blank` has no viewport metadata and reports the browser's default 980px layout viewport. SVG nodes are not HTMLElements and zero-area stroked lines are not Playwright-visible: read labels with `textContent()` and assert line presence/coordinates instead of using `innerText()` or `toBeVisible()`.
- Themed selects: use the shared `Select` / `SearchableSelect` portal primitives rather than native selects so triggers and open menus share Piggy tokens, keyboard semantics, collision-safe positioning, and reduced-motion behavior. Keep fixed choices standard and make dynamic category choices searchable; preserve form names/defaults through the mirrored input, keep public test IDs on the visible trigger with `data-value`, and mount the result-count live region only for searchable controls.
- Validation: Zod validates environment boundaries before clients are constructed.

## API Conventions

- Next.js App Router server/client boundaries; internal maintenance routes require constant-time bearer-secret authorization.
- Auth sessions use Supabase SSR cookies plus a signed absolute-session-start cookie enforced by the proxy and protected DAL.

## Known Pitfalls

- A one-point SVG line series produces only an `M` (move) command, which paints nothing. Time-series charts that can render on day one need an explicit point marker; when two one-point series coincide, use distinguishable marker shapes and keep a complete accessible table as the non-visual equivalent.
- Run `next typegen` before `tsc --noEmit`; fresh checkouts do not contain generated route types.
- On Windows, never edit a source file through `Get-Content -Raw` + `WriteAllText`. Windows PowerShell 5.1 reads a BOM-less UTF-8 file as the ANSI codepage, so `→` and `·` come back as mojibake and unmappable characters are replaced by `?` — data loss a diff review can miss. Use `[System.IO.File]::ReadAllText`/`WriteAllText` (which detect and preserve the BOM) or an editor tool.
- `pnpm format:check` covers `acceptance/` and `memory-bank/` as well as source, and `ci.yml` runs it _before_ lint — unformatted markdown fails the build exactly like unformatted TypeScript. A green `pnpm test`/`lint`/`build` locally says nothing about the gate CI hits first.
- Treat formatting as a required pre-commit gate, not a post-review cleanup: run `pnpm format:check` with the committed lockfile before pushing, and run `git diff --check` to catch whitespace that Prettier may not report. For every new or edited SQL migration, leave exactly one newline at EOF with no trailing blank lines. On Windows, repository-wide Prettier can be distorted by CRLF materialization, so also run Prettier against every changed supported file and rely on the Linux CI-equivalent check before declaring the branch ready.
- A family owner must never bypass another member's Personal-data RLS.
- Supabase service-role clients bypass RLS and must remain inaccessible to browsers.
- Rollback-only pgTAP files do not naturally fire deferred constraints; force them with `set constraints all immediate` in regression tests.
