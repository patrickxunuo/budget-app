# Installable, Accessible, Mobile-First PWA - Acceptance Criteria

## Description (client-readable)

Budget App installs to a phone, tablet, or desktop home screen and runs in its own window, while every number it shows still comes from the network. The shell adapts from a one-handed mobile layout with bottom navigation to a full desktop rail, follows the device's light or dark preference unless the member chooses otherwise, and remains fully operable by keyboard and screen reader. Nothing about a member's money — transactions, balances, budgets, sessions, or Plaid data — is ever stored by the service worker; only versioned application assets and a data-free offline screen are cached, so an installed copy that loses connectivity says so plainly instead of showing stale figures.

## Interface Contract

### Routes

| Method | Path                    | Auth   | Response                                                                                                        |
| ------ | ----------------------- | ------ | --------------------------------------------------------------------------------------------------------------- |
| GET    | `/manifest.webmanifest` | Public | `200` web app manifest generated by `src/app/manifest.ts` (`application/manifest+json`).                        |
| GET    | `/sw.js`                | Public | `200` service worker script, `Cache-Control: no-cache, no-store, must-revalidate`, `Service-Worker-Allowed: /`. |
| GET    | `/offline`              | Public | `200` static offline/reconnect screen. Contains no financial, account, or member data.                          |
| GET    | `/install`              | Public | `200` cross-platform install guidance (Android/Chromium, iOS/iPadOS Safari, desktop).                           |
| GET    | `/icons/*.png`          | Public | `200 image/png` versioned icon assets.                                                                          |

`src/proxy.ts` matches only `/dashboard/:path*` and `/settings/:path*`, so all four routes above stay reachable without a session and require no proxy change.

### Cache Policy (security boundary)

The service worker is **deny-by-default**. A response is written to a cache only when every condition holds:

1. `request.method === "GET"`, and
2. the request URL is same-origin, and
3. the pathname matches the static allowlist: `/_next/static/**`, `/icons/**`, `/manifest.webmanifest`, `/favicon.ico`, or exactly `/offline`, and
4. the response is `ok` and `response.type !== "opaque"`.

Everything else — `/api/**`, every application document (`/`, `/dashboard`, `/transactions`, `/accounts`, `/budgets`, `/categories`, `/settings/**`, `/sign-in`, …), every non-GET request, and every cross-origin request (Supabase, Plaid) — is passed to `fetch()` untouched and is never read from or written to a cache.

Navigation requests are network-first with **no** caching of the response; only when the network fails does the worker serve the precached `/offline` document.

Cache names are versioned (`budget-app-static-v<N>`). `activate` deletes every cache whose name is not the current one.

## Acceptance Criteria

### AC1 — Installable manifest and icon set

- [ ] `GET /manifest.webmanifest` returns `name: "Budget App"`, a `short_name` of at most 12 characters, `display: "standalone"`, `start_url: "/dashboard"`, `scope: "/"`, a stable `id`, `lang: "en-CA"`, `dir: "ltr"`, `orientation: "portrait-primary"`, and `background_color`/`theme_color` matching the light palette.
- [ ] The manifest declares 192px and 512px PNG icons with `purpose: "any"` and 192px and 512px PNG icons with `purpose: "maskable"`, all reachable at their declared paths.
- [ ] A 180px `apple-touch-icon` is linked from the document head, and `apple-mobile-web-app-*` metadata marks the app web-app-capable with a matching status-bar style and title.
- [ ] Maskable artwork keeps its mark inside the central 80% safe zone and is fully opaque so Android's mask cannot clip it.
- [ ] Icons are reproducible: `node scripts/generate-pwa-icons.mjs` regenerates every committed PNG byte-for-byte with no third-party dependency.

### AC2 — Cross-platform install guidance

- [ ] `/install` documents installation for Android/Chromium, iOS/iPadOS Safari (Share → Add to Home Screen), and desktop Chrome/Edge, with all instructions present in the DOM rather than gated behind user-agent sniffing.
- [ ] The section matching the visitor's platform is marked as the current one; detection failure degrades to showing all sections equally.
- [ ] When the browser fires `beforeinstallprompt`, an **Install Budget App** button appears and calls `prompt()`; the button is absent when the event never fires.
- [ ] When the app is already running in `display-mode: standalone`, the page says so instead of repeating the instructions.
- [ ] The install entry point is reachable from the application shell and the landing page.
- [ ] The persistent application header hides its install entry point in standalone PWA mode, where the app is already installed.

### AC3 — Mobile-first shell with a desktop layout

- [ ] Below the `lg` breakpoint the shell renders a fixed bottom navigation with Overview, Accounts, Transactions, Budgets, and Categories; at `lg` and above it renders the existing sticky rail and no bottom bar.
- [ ] Every navigation target is at least 44×44 CSS pixels.
- [ ] The active route carries `aria-current="page"` in both the rail and the bottom bar, and is distinguished by more than colour.
- [ ] The shell honours `env(safe-area-inset-*)` at the top, bottom, left, and right, and the document opts in with `viewport-fit=cover`.
- [ ] Page content is not obscured by the bottom bar (the scroll container reserves its height plus the bottom safe-area inset).
- [ ] No horizontal overflow at 390px, 768px, and 1280px widths.

### AC4 — Light and dark themes, device preference by default

- [ ] The default preference is `system`; with no stored choice the palette follows `prefers-color-scheme`.
- [ ] A fresh install follows the device theme; one compact icon button switches between explicit Light and Dark choices, and that choice persists across reloads in `localStorage`.
- [ ] The chosen theme is applied by an inline script before first paint, so a hard reload never flashes the wrong palette.
- [ ] `<meta name="theme-color">` is declared for both colour schemes, and `color-scheme` is set so native form controls and scrollbars match.
- [ ] The toggle is a labelled radio group operable by keyboard, and the selected option is conveyed to assistive technology.
- [ ] Storage being unavailable or holding a bogus value falls back to `system` without throwing.

### AC5 — WCAG AA

- [ ] Every token pair used for text meets a contrast ratio of at least 4.5:1, and every non-text/large-text pair at least 3:1, in **both** themes; this is asserted by a test that reads the palette out of `src/app/globals.css`.
- [ ] A "Skip to content" link is the first focusable element and moves focus to the main region.
- [ ] Every interactive element has a visible `:focus-visible` indicator with at least a 3:1 contrast against its background.
- [ ] Controls without visible text have accessible names; the navigation landmarks are labelled.
- [ ] `prefers-reduced-motion: reduce` suppresses transitions and animations (existing behaviour is preserved and extended to new UI).
- [ ] Status is never conveyed by colour alone — online/offline, update-available, and active-navigation states all carry text or shape.

### AC6 — The service worker never caches financial data

- [ ] Executing `public/sw.js` against synthetic `fetch` events proves that requests to `/api/transactions`, `/api/dashboard`, `/api/budgets`, `/api/plaid/*`, `/auth/confirm`, and any cross-origin Supabase/Plaid URL are neither read from nor written to any cache.
- [ ] Application documents (`/dashboard`, `/transactions`, `/accounts`, `/budgets`, `/categories`, `/settings/members`) are never cached, even on a successful navigation.
- [ ] Non-GET requests are never cached.
- [ ] Only `/_next/static/**`, `/icons/**`, `/manifest.webmanifest`, `/favicon.ico`, and `/offline` are cacheable, and only when the response is `ok` and not opaque.

### AC7 — Offline and reconnect

- [ ] `install` precaches the offline shell (`/offline`, the manifest, and the icons) and the worker survives a partial precache failure without breaking the install.
- [ ] A failed navigation while offline serves the precached `/offline` document, which explains that financial data is deliberately unavailable offline and offers a retry.
- [ ] A connectivity banner appears when the browser goes offline and disappears when it returns, announced politely via `role="status"`.
- [ ] The offline screen and banner never render account, balance, or transaction values.

### AC8 — Updates without stale UI or refresh loops

- [ ] The worker does not call `skipWaiting()` during `install`; a waiting worker activates only after the page posts `{ type: "SKIP_WAITING" }`.
- [ ] When a new worker is waiting **and** a controller already exists, the app surfaces an accessible "new version" prompt with an explicit refresh action.
- [ ] `controllerchange` reloads the page at most once, guarded by a flag, so an update cannot loop.
- [ ] The first-ever installation (no existing controller) shows no prompt and performs no reload.
- [ ] `activate` claims clients and deletes every non-current cache.
- [ ] `/sw.js` is served with `Cache-Control: no-cache, no-store, must-revalidate` so a new worker is always discovered.

### AC9 — Accessible charts and non-colour status

- [ ] The dashboard cash-flow chart keeps a textual equivalent (a captioned data table) alongside the decorative bars, which stay hidden from assistive technology.
- [ ] Budget threshold, sync health, and connectivity states each pair their colour with text or a shape.

### AC10 — Verification

- [ ] `pnpm lint`, `pnpm typecheck`, `pnpm test`, and `pnpm build` are green.
- [ ] `e2e/pwa.spec.ts` covers manifest and icon delivery, the install page, the offline screen, bottom-nav-versus-rail rendering, the skip link, theme switching, and the absence of horizontal overflow at phone, tablet, and desktop widths, on both the desktop and mobile Playwright projects.

## Out of Scope

Push notifications, background sync, native or React Native clients, and any offline access to financial data — all explicitly deferred by the ticket.
